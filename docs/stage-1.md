## 1. Модель предметной области

### 1.1 Участники
| Участник | Природа | Ключевые атрибуты / полномочия |
|---|---|---|
| Сотрудник | человек-участник кампаний | `masterId` (уникален в компании, не переиспользуется), признак активности, теги аудитории, 1 личный кошелёк |
| Владелец кампании | действующий сотрудник, назначен админом | полномочие на конкретную кампанию; распоряжается её бюджетом, не увеличивает его |
| Администратор компании | сотрудник службы/админ | управление профилями, ресурсами, кампаниями, владельцами, бюджетами, разрешениями интеграций; коррекции; видит данные своей компании |
| Корпоративная интеграция | доверенный внешний источник | действия только по явно выданным разрешениям (B04): передача прогресса / начисление из бюджета / списание для системы покупок |
| Система покупок | зарегистрированная корпоративная система | инициирует/отменяет списания по разрешению; видит только свою историю операций |

### 1.2 Сущности
| Сущность | Ключ уникальности | Существенные поля |
|---|---|---|
| Компания | — | часовой пояс (для эксперимента Europe/Tallinn) |
| Сотрудник | (компания, masterId) | активность, теги аудитории |
| Кошелёк | 1 на сотрудника | балансы по ресурсам (≥ 0); одинаковый ресурс из разных кампаний — на одном балансе |
| Ресурс | код в компании (без учёта регистра), неизменяем | название, статус (активен/архив) |
| Кампания | (компания, сезон, код) | название, описание, владелец, сезон, сроки, аудитория, набор ресурсов, состояние |
| Стрим | код в кампании | название, коллекция заданий, общий накопительный прогресс, вехи, аудитория (наследуется) |
| Задание | код в стриме | цель (>0), периодичность, очки стрима (≥0), список ресурсных наград (может быть пуст), наборы тегов аудитории (B11) |
| Период | календарный (день/месяц/квартал/полугодие/год) | начало включено, конец исключён |
| Прогресс | (сотрудник, задание, период) | значение ≤ цели |
| Событие | (компания, источник, номер события) | сотрудник, задание, переданное/зачтённое увеличение, время принятия системой |
| Завершение | (сотрудник, задание, период), не более 1 | — |
| Очки стрима | (сотрудник, стрим, сезон) | сумма очков завершённых заданий |
| Веха | стрим | порог (>0), достижение |
| Достижение | код в компании | название, описание; выдача ≤1 раз/сезон/сотрудник |
| Челлендж | стрим | начало, конец (внутри кампании); счёт = сумма зачтённых увеличений |
| Рейтинг | челлендж | masterId, счёт, место |
| Бюджет | (кампания, ресурс) | остаток = выделения − начисления + отмены (≥ 0) |
| Операция | (компания, инициатор, вид операции, номер) | ресурсы/количества, время, основание, результат, причина отказа |
| Выписка | заказ | интервал, ресурс(ы), состояние, зафиксированный набор данных |

### 1.3 Состояния и переходы (кратко, детали в §3)
- Кампания: **Черновик → Опубликована → Архив** (архив необратим; черновик удаляется целиком).
- Ресурс: **Активен → Архив** (необратимо).
- Выписка: **ожидает → формируется → готов**; допускаются **ошибка** и **удалён**.
- Операция: результат **проведена / отклонена** (один неизменяемый результат на номер).
- Завершение: **не завершено → завершено** (однократно).
- Достижение: **не получено → получено** (≤1 раз за сезон).
- Кошелёк: баланс любого ресурса **≥ 0** всегда.

### 1.4 Существенные связи
- Кампания → Стрим → Задания; Стрим → Вехи → Достижения (вехи принадлежат стриму, B08/B29); Стрим → Челлендж → Рейтинг.
- Кампания + Ресурс → Бюджет; начисление: бюджет −k, кошелёк сотрудника +k (атомарно).
- Кошелёк объединяет одинаковый ресурс из разных кампаний на один баланс (B22b); отсюда общий остаток ресурса влияет на списания и отмены (B26c).
- Сотрудник → (прогресс, завершения, очки стрима, достижения, кошелёк, выписки).
- Операция → Отмена (полная, ссылка на оригинал); у исходной операции ≤1 успешная отмена.
- Сезон: новые кампании создаются заново; кошелёк/операции/достижения прошлых сезонов сохраняются; бюджет не переносится; очки стрима и прогресс начинаются с нуля.

**Границы интеграции (D01).** Полномочия интеграции ограничены тем, что ей явно выдано админом (B04): передача прогресса по кампании, начисление указанных ресурсов из её бюджета, списание указанных ресурсов для определённой системы покупок; дополнительно — возврат по собственной успешной трате (B27) и доступ к собственной истории операций (B04c/B28). **Сочетание ролей сотрудника и владельца (D01).** Владелец — одновременно сотрудник. Каждое действие авторизуется по одной применимой области; полномочия не складываются произвольно.

## 4. Проверяемые сценарии Given/When/Then

Ожидаемые суммы вычислены из правил B14/B19/B20/B24–B27. **Начальное состояние кошелька задаётся явно в каждом сценарии (D04):** баланс ресурса — агрегированный общий остаток по ресурсу, объединяющий поступления из разных кампаний (B22b). Базовый контекст: сотрудник активен и в аудитории кампании и задания, источник/система разрешены, кампания опубликована и в сроках, ресурсы доступны.

### 4.1 Обязательные сценарии

**S1. Основной путь (два ресурса).** Given: кошелёк пуст (A=0, B=0); задание T (цель 3, очки стрима 5, награда 10 A + 2 B); бюджеты A=10, B=2. When: источник передаёт событие E1 с увеличением +5. Then: прогресс = min(3, 0+5) = 3, зачтено 3 (переданное 5); завершение одно; очки стрима +5; начислены 10 A и 2 B; бюджеты A=0, B=0; кошелёк A=10, B=2.

**S2. Недостаток одного ресурса.** Given: кошелёк пуст (A=0, B=0); бюджеты A=10, B=1; событие завершает T. When: обработка события. Then: ни A, ни B не начислены (all-or-nothing, B20a); завершение есть; очки стрима добавлены; бюджеты без изменений (10 и 1); кошелёк A=0, B=0; отказ «недостаточно бюджета» зафиксирован. Затем пополнение B → 2: старое решение не меняется (B20c).

**S3. Повтор отказа (трата).** Given: кошелёк A=3; трата W1 на 7 отклонена (кошелёк A=3). When: начислено 10 (кошелёк A=13), затем повтор W1. Then: повтор W1 остаётся отклонённым (кошелёк A=13). Новая трата W2 на 7 → проведена, кошелёк A=6 (B24d).

**S4. Конкурирующие траты.** Given: кошелёк A=10; две одновременные траты W1 и W2 по 7. When: обе обрабатываются. Then: одна проведена (кошелёк A=3), другая отклонена; A=3, не −4 (B22d, E05).

**S5. Конкурирующие награды за последний бюджет.** Given: кошелёк A=0; бюджет A=10; два задания завершаются одновременно, каждое с наградой 10 A. When: обе награды обрабатываются. Then: одна проведена (бюджет 0, кошелёк A=10), другая отклонена «недостаточно бюджета» (бюджет 0, не −10); оба завершения и очки сохранены (B19e, B20f, E04).

**S6. Конкурирующие отмены (возврат).** Given: кошелёк A=10; проведена трата 7 (кошелёк A=3). When: два одновременных запроса отмены той же траты. Then: один возврат (кошелёк A=10), второй не увеличивает баланс повторно (B25d/B27e, E07).

**S7. Отмена пакета награды.** Given: начислено 10 A + 2 B (кошелёк A=10, B=2); затем потрачен 1 B (кошелёк A=10, B=1). When: полная отмена награды (B26). Then: отклонена целиком (нехватка B), возврат A в бюджет не происходит; кошелёк A=10, B=1; бюджеты без изменений (E08).

**S8. Граница периодов (день).** Given: событие принято системой 23:59:59 дня D. When: источник повторяет его после полуночи (день D+1). Then: повтор возвращает прежний результат и остаётся в дне D; новое событие в 00:00 D+1 относится к новому периоду, цель не уменьшена (B13c, B16d, E11).

**S9. Потеря прав (блокировка).** Given: событие E1 принято, начисление N проведено, сотрудник заблокирован (неактивен). When: источник повторяет E1; система покупок инициирует новую трату. Then: повтор E1 проверяет активность — не принимается (B16e, B05b+B11e); новая трата отклонена (B23c); заработанные средства, история и место в рейтинге не исчезают (B05d); админ может отменить N по B26 (B05c).

**S10. Снимок выписки.** Given: заказана выписка за интервал; первое успешное начало формирования фиксирует набор данных (балансы/движения на этот момент). When: после фиксации приходят новые движения; выполняется повторная попытка формирования. Then: новые движения не дописываются; повторная попытка использует тот же набор; готовый файл и состав не меняются (B36b–e).

## 5. Неоднозначности и противоречия

### 5.1 Реальные бизнес-неоднозначности (остаются на решение заказчика; указаны допустимые разные результаты)

| ID | Источник | Суть | Какие разные результаты допускает |
|---|---|---|---|
| **RA1** | B32 | Значение «первых N участников» рейтинга не задано. | Любое значение N (0, фиксированное, «все») меняет границу видимости рейтинга. |
| **RA2** | B35 | «Временной интервал» выписки не детализирован (произвольный или выровненный по периодам/кампаниям). | Произвольный vs выровненный интервал меняет состав выписки. |
| **RA4** | B26 | Применима ли B26g («блокировка не мешает коррекции») к владельцу, или только к администратору. | (а) владелец может отменить награду заблокированному получателю; (б) только администратор — различаются полномочия владельца. |

Инженерные условия для сверки RA1/RA2 не предоставлены; собственное предложение за решение организатора не выдаётся — вопросы остаются открытыми. Момент снимка выписки уже задан B36 (первое успешное начало формирования, не заказ) и отражён в S10 и §3.2.

### 5.2 Поведение, однозначно выводимое из исходника (не требует решения заказчика)
Сочетания правил из разных пунктов уже заданы и не выносятся на заказчика (D02):
- **Блокировка → неактивен → новые события прогресса не засчитываются** (B05b + B11e + B16e).
- **Наборы «существенных данных»**: событий (сотрудник, задание, увеличение — B16c) и операций (сумма, ресурс, получатель, кампания, система покупок — B24c) заданы исходником.
- **Места в рейтинге заблокированных/неактивных не исчезают** (B05d).
- **Единый чек-лист приёма события** выводится из B05/B11/B14/B15/B16/B20; его формализация — техническая задача, не бизнес-правило.
- **«Разрешённый ресурс» для ручного начисления** = ресурс из набора кампании (B08e + B21a); начисление без бюджета → отказ по B19/B21.
- **Получатель ручной награды** должен быть активным участником действующей кампании (B03c/B21a); начисление любому активному сотруднику вне кампании не предусмотрено.
- **Семантика состояний выписки** (B36a–e) задана; точный момент фиксации при «успешном начале формирования» — техническая деталь.
